面向学习和复现实验的运行环境说明。报告只分析当前文件夹代码，不改动原始程序。

一、总体判断

结论：这个源码目录分成两大类：一类是普通 Python 视觉识别/图像处理脚本，另一类是 ROS1 + Gazebo 的机器人导航仿真工程。普通视觉脚本可以在 Windows 或 Linux 上跑；ROS 应用建议放到 Ubuntu + ROS1 Noetic 环境下跑。
8 个 Python 脚本 红绿灯、垃圾桶、楼宇火灾、人员识别、巡线、ROS 导航点发布等。
5 个 ROS 包 gazebo_map、gazebo_nav、gazebo_pkg、jie_ware、pid_planner。
模型文件齐全 包含 YOLO ONNX、PaddleOCR 推理模型、地图 PGM/YAML、Gazebo world/URDF。
已有构建痕迹 ROS 工程曾在 /home/demo/test_ws 用 Python3、OpenCV4、GCC9 构建过，强烈指向 Ubuntu 20.04 + ROS Noetic。

二、普通 Python 视觉脚本

巡线/巡线.py
可 Windows 跑 OpenCV 图像处理

功能：读取视频，逐帧做车道线/巡线检测，输出带方向、误差、转向角度标注的视频。

依赖：opencv-python、numpy、pillow。需要能弹出 OpenCV GUI 窗口。

运行方式：进入 巡线 目录后运行，程序会让你输入视频路径。

cd 巡线
python 巡线.py

学习重点：自适应阈值、ROI 区域、黑色像素分组、车道中心线、卡尔曼滤波、方向角计算。

红绿灯/light.py
可 Windows 跑 FastDeploy YOLOv8 ONNX

功能：用 红绿灯/moxing/best.onnx 检测 images 下的红、绿、黄交通灯图片，并输出到 output_images。

依赖：fastdeploy-python、opencv-python。脚本默认置信度阈值为 0.8。

cd 红绿灯
python light.py

注意：模型路径是相对路径 moxing/best.onnx，所以要在 红绿灯 文件夹内运行。

垃圾桶/垃圾桶.py
可 Windows 跑 FastDeploy YOLOv8 ONNX

功能：识别垃圾桶类别和是否已投放，类别包括可回收物、有害垃圾、厨余垃圾、其他垃圾。

依赖：fastdeploy-python、opencv-python、numpy、pillow。需要中文字体，目录中有 moxing/ziti.ttf。

cd 垃圾桶
python 垃圾桶.py

注意：脚本会显示图片窗口，按键继续，ESC 退出。

人/human.py
可 Windows 跑 FastDeploy + ONNX Runtime YOLOv5 ONNX

功能：从 images 随机选最多 10 张图，识别职业人员和普通人员，并生成 result/summary_report.jpg。

依赖：fastdeploy-python、opencv-python、numpy、pillow。代码显式使用 CPU 和 ONNX Runtime 后端。

cd 人
python human.py

注意：模型文件是 human.onnx，字体文件是 ziti.ttf，都按相对路径查找。

楼宇火灾识别/楼宇火灾.py
可 Windows 跑 FastDeploy YOLOv8 + PPOCRv3

功能：检测楼宇、识别楼宇名称、检测楼层和火焰，判断某楼某层是否着火。

依赖：fastdeploy-python、opencv-python、numpy、pillow、rich。模型包括 building.onnx、fire.onnx 和 OCR 下的 PaddleOCR 推理文件。

cd 楼宇火灾识别
python 楼宇火灾.py

学习重点：先检测建筑框，再裁剪区域做 OCR，再在建筑区域内检测楼层和火焰，最后把火焰中心点匹配到楼层框。

楼宇火灾识别/building.py
摄像头实时版 路径硬编码

功能：打开默认摄像头，运行 30 秒左右触发一次楼宇检测。

依赖：fastdeploy-python、opencv-python、numpy，并且需要本机有摄像头。

重要限制：模型路径写死为 /home/eaibot/yolov5/models/building.onnx。如果这台机器没有这个 Linux 路径，按原样运行会失败。

视觉脚本依赖安装参考

普通 OpenCV 脚本可先安装：

pip install opencv-python numpy pillow rich

FastDeploy 的安装跟 Python 版本、CPU/GPU、操作系统有关。建议用 Python 3.8 到 3.10，并优先选择 CPU 版先跑通。若使用 GPU，需要匹配 CUDA、cuDNN、ONNX Runtime 或 Paddle 后端。

三、ROS 应用环境

核心判断：ROS应用 是一个 catkin 工作空间，里面有 src、build、devel。构建缓存显示它原来位于 /home/demo/test_ws，使用 /usr/bin/python3、GCC9、OpenCV4，最匹配的环境是 Ubuntu 20.04 + ROS Noetic。

ROS 运行链路

  1. roslaunch gazebo_nav nav11.launch 启动 Gazebo 场景和机器人。
  2. map_server 加载 gazebo_map/map/map11.yaml。
  3. jie_ware/lidar_loc 用激光雷达和地图做定位。
  4. move_base 使用 global_planner/GlobalPlanner 做全局路径，使用 pid_planner/PIDPlanner 做局部速度控制。
  5. ROS应用/nav.py 作为动作客户端，向 move_base 连续发送 8 个导航点。
地图路径问题：map1.yaml 和 src/gazebo_map/map/map11.yaml 里面的 image 都写成了 /home/demo/test_ws/... 这样的绝对路径。若你的工作空间不是这个路径，地图服务器可能找不到 PGM。学习时要知道这是移植 ROS 工程最常见的问题之一。

五、常见注意事项

1. 相对路径要求很强

多数 Python 脚本都用类似 images、moxing/best.onnx、result 这样的相对路径。运行时必须先 cd 到对应子目录，否则会找不到模型或图片。

2. FastDeploy 版本要匹配

这些脚本依赖 FastDeploy 的 fd.vision.detection.YOLOv8、YOLOv5、fd.vision.ocr API。建议用同一套 Python 环境先跑一个最小模型加载测试，再批量跑图片。

3. OpenCV GUI 不能在纯命令行环境显示

代码里大量使用 cv2.imshow。如果在服务器、WSL 无图形桌面、远程终端里运行，会因为没有显示环境而失败。需要本地图形桌面或配置 X11。

4. ROS 不适合直接在 Windows 跑

当前 ROS 工程是 ROS1 catkin 工作空间，含 Gazebo、RViz、C++ 插件。最省事的环境是 Ubuntu 20.04 虚拟机或双系统。Windows 原生运行成本很高。

5. 复制 ROS 工作空间后要重新构建

build 和 devel 记录了旧路径 /home/demo/test_ws。换机器后通常应在 Linux 中重新执行 catkin_make，并重新 source devel/setup.bash。

六、建议学习路线

  1. 先跑普通视觉脚本：从 巡线/巡线.py 开始，它不依赖深度学习框架，只需要 OpenCV、NumPy、Pillow。
  2. 再看 YOLO 推理：比较 红绿灯/light.py、垃圾桶/垃圾桶.py、人/human.py，理解模型加载、图片读取、置信度过滤、画框保存。
  3. 学习组合任务：看 楼宇火灾识别/楼宇火灾.py，它把目标检测、OCR、空间关系判断串成完整业务流程。
  4. 最后学习 ROS：先看 gazebo_nav/launch/nav11.launch 明白节点启动顺序，再看 pid_planner/src/pid_planner.cpp 理解 move_base 局部规划器接口。
一句话记忆：视觉脚本靠 Python 包和模型文件跑；ROS 应用靠 Ubuntu + ROS Noetic + catkin + Gazebo 导航栈跑。两个环境可以分开学，不需要一开始混在一起。
